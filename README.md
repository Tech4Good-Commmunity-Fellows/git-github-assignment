# Git & GitHub Workshop

## Project Introduction

This repository is an internal-style engineering onboarding project for new software engineering fellows learning Git and GitHub through hands-on documentation contributions.

Participants will practice common collaboration workflows by working in branches, editing documentation, opening pull requests, reviewing peers, and resolving merge conflicts.

## Workshop Objective

The objective of this workshop is to help fellows build confidence with everyday Git and GitHub tasks in a realistic repository that mirrors a team documentation project.

By the end of the workshop, each participant should be able to:

- Create and manage a feature branch
- Make meaningful commits with clear messages
- Edit documentation in a structured repository
- Open and review pull requests
- Pull changes from the main branch
- Handle merge conflicts safely
- Follow a lightweight team contribution process

## Learning Outcomes

After completing the workshop, participants should understand:

- The purpose of repositories, branches, commits, and pull requests
- How to collaborate without directly editing the main branch
- How documentation changes move through a review process
- How to keep local work in sync with upstream changes
- How to approach merge conflicts calmly and methodically

## Expected Git Workflow

1. Clone the repository locally.
2. Create a feature branch using the repository convention.
3. Make focused edits in small, meaningful commits.
4. Push the branch to GitHub.
5. Open a pull request for review.
6. Respond to review feedback.
7. Pull the latest changes if another pull request is merged.
8. Resolve any merge conflicts before merging your work.
9. Delete the feature branch after merge.

## Contribution Process

All workshop contributions should follow the process below:

1. Read the assignment in [ASSIGNMENT.md](ASSIGNMENT.md).
2. Review the contribution guidelines in [CONTRIBUTING.md](CONTRIBUTING.md).
3. Work inside a branch named `feature/<your-name>`.
4. Update the required participant, docs, and resources files.
5. Commit in small steps with descriptive messages.
6. Open a pull request using the provided template.
7. Request and complete one peer review.
8. Merge only after checks and review feedback are complete.

## Repository Rules

- Keep edits professional, clear, and beginner-friendly.
- Use Markdown headings and formatting consistently.
- Avoid filler text; use placeholders such as `> TODO: Explain this concept.`
- Make documentation contributions concise and purposeful.
- Do not push directly to the main branch.
- Keep commits meaningful and easy to review.
- Respect review feedback and maintain a constructive tone.

## Getting Started

1. Clone the repository.
2. Open the project in your editor.
3. Read the assignment and contribution guide.
4. Create your feature branch.
5. Fill in your participant profile.
6. Improve one documentation page in `docs/`.
7. Complete the shared command reference in `resources/commands.md`.
