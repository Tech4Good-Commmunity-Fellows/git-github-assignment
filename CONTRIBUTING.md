# Contributing Guide

Thank you for contributing to the Git & GitHub workshop repository. This project is designed for learning, so contributions should be clear, well-scoped, and easy to review.

## Branch Naming Convention

Use the following format for all workshop branches:

```text
feature/<your-name>
```

Examples:

- `feature/leela`
- `feature/nikita`
- `feature/pooja`

## Commit Message Guidelines

Write commit messages that describe a single meaningful change.

Recommended style:

- Start with an action verb
- Keep the message short and specific
- Avoid vague messages such as `update file` or `changes`

Examples:

- `Add participant profile template`
- `Clarify branching workflow`
- `Document Git status command`

## Pull Request Process

1. Push your branch to GitHub.
2. Open a pull request against the main branch.
3. Complete the pull request template fully.
4. Request a peer review.
5. Address review comments with follow-up commits.
6. Merge only after the PR is approved and checks are complete.
7. Delete the feature branch after merge.

## Code Review Expectations

When reviewing another participant’s pull request:

- Read the summary carefully before reviewing changes.
- Check whether the requested assignment tasks were completed.
- Leave comments that are specific and respectful.
- Ask questions when something is unclear.
- Approve only when the work is complete and understandable.

## Repository Etiquette

- Keep communication respectful and professional.
- Work in small, reviewable chunks.
- Avoid force pushing unless a facilitator asks for it.
- Do not edit another participant’s files unless the assignment asks you to.
- Keep your branch up to date with the latest main branch changes.

## Best Practices

- Pull the latest changes before starting work.
- Commit frequently enough to preserve progress, but not so often that commits become noisy.
- Prefer concise documentation improvements over large unrelated edits.
- Use pull requests to describe intent and context.
- Resolve merge conflicts carefully and verify the final result.
- Delete local and remote feature branches after they are merged.

## Questions

If you are unsure about the workflow, ask a facilitator before making changes that affect other participants.
